🤝 结合使用：三个模式

根据场景选择最合适的 Agent 组合方式。

1
完整闭环（最佳实践 ⭐）
Security Agent 渗透测试 → 发现 SG 配置风险（事前）
                                              │
     问题真的发生了 ────────────────────────────┘
     │
     ▼ DevOps Agent 事件集成主动响应（只读权限）
     ├─ CloudWatch 告警自动触发
     ├─ 关联多信号分析
     └─ 推送根因结论（MCP + Slack）
           │
           ▼ Kiro-CLI（堡垒机，用户 IAM 角色权限）
           ├─ 通过 MCP 拉取 Agent 结论
           ├─ aws cli / kubectl 验证
           ├─ 生成 Terraform 修复代码
           └─ 人工确认执行 ✅
                │
                ▼ Security Agent 审查修复代码 + 更新渗透用例
                ▼ DevOps Agent 学习模式 → 下次主动预警
2
Kiro-CLI 为主（快速排障场景）
开发者在堡垒机发现问题
     │
     ▼ Kiro-CLI + AWS CLI（用户 IAM 角色权限）
     ├─ kubectl describe pod / aws efs describe-mount-targets
     ├─ 分析日志 → 定位根因
     ├─ 生成修复命令 / IaC 代码

06 · Selection

💡 选型指南

常见问题解答 + 场景快速推荐。

常见问题解答

"Kiro 和 DevOps Agent 都能分析日志，区别是什么？" +
权限和触发方式不同：Kiro 继承你的 IAM 角色权限，能查能改，但需要人主动发起；DevOps Agent 只有只读权限，但能与事件集成自动触发，7×24 主动响应。一个是"带工具的工程师"，一个是"只读监控大屏"。
"为什么 DevOps Agent 不能执行修复？" +
设计哲学是只读——生产环境变更必须经过人确认。Agent 负责发现和分析，Kiro 负责生成修复代码，人确认后执行。权限分离是最安全的模式。
"Security Agent 和另外两个什么关系？" +
Security Agent 做渗透测试——主动找漏洞和暴露面，在问题发生之前就阻断。另外两个是问题发生后的发现和修复。三者是事前-事中-事后的关系。
"我们怕 AI 乱改生产环境" +
三层安全保障：DevOps Agent 只读不改；Kiro-CLI 继承用户 IAM 权限且需人工确认；Security Agent 审查修复代码。

场景 → 快速推荐

需求场景…推荐原因
"开发者在堡垒机排障"Kiro-CLI直接跑堡垒机 + AWS CLI，用户权限
"凌晨出问题没人处理"DevOps Agent事件集成主动响应，只读权限
"想做安全漏洞扫描"Security Agent渗透测试核心能力
"自动发现 + 手动修复"DevOps + Kiro (MCP)只读发现 + 用户权限修复
"怕 AI 乱改环境"三者结合只读 + 用户权限 + 安全审查 = 三层保障
"出海多区域合规"Security Agent 为主渗透测试 + 合规映射
07 · Scenarios

典型场景 Playbook

场景 A · EKS Pod 无法挂载 EFS
Step 1: Pod 启动失败，挂载 EFS 超时
Step 2: Kiro-CLI（堡垒机）+ AWS CLI
        （用户 IAM 权限）→ 拉取日志
Step 3: 分析日志 → 定位根因
        （SG/子网/CSI driver）
Step 4: 生成修复代码
        （Terraform / AWS CLI）
Step 5: 人工确认执行修复 ✅
场景 B · 出海安全合规
Step 1: Security Agent → 渗透测试
        + 合规审计
Step 2: Kiro-CLI → 生成合规修复代码
Step 3: DevOps Agent → 部署后
        持续只读监控
场景 C · 7×24 EKS 主动运维
Step 1: DevOps Agent 事件集成（只读）
        → 主动响应告警
Step 2: 自动调查 → 推送根因结论
Step 3: Kiro-CLI → 生成修复代码
        （用户 IAM 权限）
Step 4: Security Agent → 审查修复安全性
